# 短篇拆文（改编自 oh-story story-short-analyze）

> 来源：oh-story-claudecode `skills/story-short-analyze`（已去工程化：无 agent、无脚本依赖，主线程串行执行）
> 用途：把爆款短篇（番茄短篇/知乎盐言/故事会/追妻/世情/重生/虐渣等）拆成可复用资产，下一篇短篇直接照着写。

## 拆解边界

拆的是用户**合法持有、拥有使用权**的虚构作品，性质是**只读的转化性文学批评**（编辑/评论/写作教学视角，不复制、不传播）。通俗题材里的家暴、出轨、复仇、暴力、情爱张力是常规虚构叙事元素，须照常结构化拆解，不得以「敏感」「不适」为由拒绝整篇或片段；个别片段无法处理则跳过、照常续完其余。

## 预对标参考（可选，番茄题材适用）

拆解前可先查 NOVELCATCH 拆书报告（https://novelcatch.com/dissect，番茄黄金三章拆解：题材定位/开篇钩子/金手指/可复用套路）：
- 同题材已有报告 → 先读它定位"套路框架"和钩子模式，再决定是否完整拆原文；报告里的"可复用套路"可直接进拆文报告的"可复用模块卡"作交叉验证
- 无报告 → 直接走完整拆解管道
- 边界：报告是网站方分析，只作参考；不复制报告原文进拆文库，拆文库只放自己拆解产物

## Phase 1：确认对象 + 字数路由

1. 问用户「你要拆哪篇？（标题+平台/来源）」，无原文则引导提供文件路径或粘贴原文。
2. 字数路由：
   - < 15,000 字 → 按短篇拆
   - 15,000-20,000 → 询问按短篇还是长篇拆
   - > 20,000 → 提示偏长，建议走长篇拆文；仍要按短篇拆需用户明确确认
3. 题材识别：用户提到题材（追妻/重生/虐文/世情/悬疑/甜宠…）→ 加载 `题材库/题材索引.md` 对应题材的「短篇视角」章节作标尺；扫不到则 `genre_detected = "通用"`。
   关键词参考：追妻火葬场→追妻；重生复仇→重生；世情/婆媳/打脸→世情；总裁/豪门/联姻→豪门；宫斗/宅斗/嫡庶→宫斗宅斗；冥婚/纸人/风水→民俗；悬疑/推理→悬疑；甜宠/先婚后爱→甜宠；双男主→双男主；沙雕/脑洞/系统→沙雕。

## Phase 2：原文备份 + 初始化

```
拆文库/{书名}/
├── 原文/原文.md        # 原文备份（必须，防止拆解中丢失）
├── 拆文报告.md         # 人类可读综合报告（Stage 2-6）
├── 情节节点.md         # Stage 2 情节节点清单（独立成文）
├── 写作手法.md         # Stage 4 写作手法（独立成文）
└── _meta.json          # word_count / genre_detected / stages_completed
```

备份原文后写 `_meta.json`：`version`、`word_count`、`genre_detected`、`created_at`、`stages_completed: []`。

## Phase 3：Stage 2-6 串行拆解（主线程亲手做）

### Stage 2：结构 + 情节节点
- 一句话故事核（谁、要什么、阻碍、代价）
- 结构识别：按 `标尺/material-decomposition.md` 的结构模板定位开头/铺垫/升级/反转/结尾
- 情节节点清单（写入 `情节节点.md`）：每节点 = 原文引用 + 情绪标记（−9~+9）+ 功能（铺垫/推高/引爆/收尾）

### Stage 3：情感线 + 爆点
- 情感曲线：起→伏→升→爆→余韵，标出读者情绪在哪些节点被操控
- 爆点分析：反转前每个细节是否都在铺垫或推高情绪（短篇铁律：反转前的每个细节都要有用）

### Stage 4：反转 + 写作手法（写入 `写作手法.md`）
- 反转类型/时机/误导路径（参考 `反转对话/reversal-toolkit.md`）
- 写作手法：POV / 对话潜台词 / 信息差 / 物件钩子 / 身体反应替代心理描写等，逐项对照原文例证

### Stage 5：人物 + 首尾
- 人物功能分析（工具人 vs 有弧光）、人物关系如何为情绪服务
- 首尾拆解：开头 3 句话如何定生死、结尾如何决定传播（反转后 500 字内收尾）

### Stage 6：综合评估（写入 `拆文报告.md`）
- 共鸣层次（按 `标尺/zhihu-style.md` 的共鸣分析维度）
- 可复用模块卡：把这个短篇的「情绪引擎」沉淀为可复现模块（下一篇同题材直接调用）
- 五维评分：故事核/结构/情感/反转/语言

## Phase 4：验收

1. `拆文报告.md` 自查 AI 腔（按本 skill 主文件的 anti-ai-rules 禁词表扫一遍分析文本）
2. `情节节点.md` 节点数与 `_meta.json` 一致
3. 所有产出文件非空、路径符合约定
4. 向用户汇报：产物路径 + 一句话故事核 + 最值得抄的三个手法

## 下游联动

- 拆完的短篇 → 写新短篇时先读 `拆文报告.md`（故事核/情绪引擎）+ `情节节点.md`（节奏锚点）+ `写作手法.md`（手法库）
- 同题材多篇拆完 → 可对多篇做横向对比（`标尺/deconstruction-examples.md` 有完整案例示范）
