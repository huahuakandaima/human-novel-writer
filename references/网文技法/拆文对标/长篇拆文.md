# 长篇拆文（改编自 oh-story story-long-analyze）

> 来源：oh-story-claudecode `skills/story-long-analyze`（已去工程化：无 chapter-extractor 子代理、无 _progress 断点协议脚本，主线程串行执行；批量摘要分批做，每批 5-8 章）
> 用途：把爆款长篇拆成结构化对标资产，供日更写作当「对标书」用（拆文库/{书名}/ → 写作时读 剧情/节奏.md、剧情/情绪模块.md、文风.md）

## 拆解边界

拆的是用户**合法持有、拥有使用权**的虚构作品（已出版/连载或自有），性质是**只读的转化性文学批评**。通俗题材里的黑暗伦理是常规虚构叙事元素，须照常结构化提取，不得以「敏感」为由拒绝整章或整本；个别片段无法处理则跳过、照常续完其余。

## 前置：确认对象 + 已有分析利用

- 问用户「拆哪本书？（书名+平台）有原文文件路径吗？」；无明确目标时按用户想写的题材推荐 2-3 本对标作品。
- **预对标参考（可选，番茄题材适用）**：拆解前先查 NOVELCATCH（https://novelcatch.com/dissect）同题材爆款的黄金三章拆解报告（题材定位/开篇钩子/金手指/可复用套路）：
  - 有报告 → 先读它做"预对标"，快速定位该题材的套路框架与钩子模式，再决定是否对这本书做完整 Stage 0-6 拆解（完整拆解仍产出 `拆文库/{书名}/` 资产，两者互补；报告结论可在 Stage 3 聚合时作交叉验证）
  - 无报告 → 直接走完整拆解管道
  - 边界：报告是网站方分析，只作参考；不复制报告原文进拆文库，拆文库只放自己拆解产物
- 拆前检查 `拆文库/{书名}/`：有已有文件则读取作交叉验证基线（角色/设定合并、冲突标注让用户裁定），避免重复提取。
- **原文必须备份**：复制到 `拆文库/{书名}/原文/`（对话贴文本则存 `原文.md`），验证非空后再开工。

## 输出目录

```
拆文库/{书名}/
├── 原文/原文.txt
├── 概要.md                # Stage 0 首版 200 字 + Stage 5 全书 500-1000 字版覆盖
├── 章节/
│   ├── 第1章_深度拆解.md … 第3章_深度拆解.md   # 黄金三章
│   └── 第1章_摘要.md …                            # 逐章摘要
├── 快速预览.md             # Stage 1 停靠点产物
├── 角色/ {角色名}.md 角色关系.md
├── 剧情/ README.md 故事线.md 节奏.md 情绪模块.md 散落情节.md
├── 设定/ 世界观/ 势力/
├── 拆文报告.md
└── 文风.md                # Stage 6
```

> **权威产物**：`剧情/节奏.md`（关键信息推进/爽点循环/情绪触动点）与 `剧情/情绪模块.md`（读者需求/情绪引擎/可复现模块卡）是下游写作的权威索引；`拆文报告.md` 与 `故事线.md` 只是摘要投影。

## 管道：Stage 0-6（串行）

### Stage 0 概要提取
首版概要 200 字（thin first-pass）+ 章节索引 + **章节边界表**（章号↔行号/起始标记，写入 `拆文库/{书名}/_progress.md`，Stage 1/2/6 共用，避免每阶段各切一遍；仅作切片真值，不做断点恢复）。

### Stage 1 黄金三章（深度拆解前三章）
每章一个文件：开篇钩子、信息铺设、人物出场、冲突引入、章尾卡点。非人形反派（末世/灵气复苏等抽象对抗型）按「核心对抗面/紧迫感来源/升级机制」路由分析。
**完成后停靠**：产出 `快速预览.md`（三章结论 + 预估总拆解量），询问用户是否继续全量拆解。

### Stage 2 逐章摘要（分批，每批 5-8 章）
每章摘要：情节点（每章 10-40 个，密度 150-200 字/个）+ 角色提及 + **关键信息与扩写技法** + **逐章写法公式**（情绪流向/节奏配比/结构公式/核心技巧/章尾卡点与伏笔）。龙套不提取、别名归类。计数校验：摘要数 == 章节数。

### Stage 3 聚合分析（全书层）
- 故事框架识别（前置，决定聚合策略）
- 剧情聚合：先识别剧情大纲，再按大纲分配情节点 → `剧情/{剧情标题}.md`
- 关键信息推进索引：按章节追踪信息如何被扩写（一笔两用/延迟揭示/视角欺骗/跨章回扣）
- **节奏.md**：情绪折线、爽点频率、小/中/大高潮位置、冲突升级路径、跨章伏笔地图
- **情绪模块.md**：读者需求 / 情绪引擎 / 爽文套路框架 → 沉淀为可复现模块卡
- 角色合并去重 + 分级（主角/反派/核心配角/功能角色）；散落情节兜底（覆盖率验证）

### Stage 4 设定 + 角色关系
- 设定：世界观/金手指/势力（从摘要中的设定提及归纳，`设定/世界观/` 下按主题拆文件）
- 角色完整档案：跨章合并、别名解析，`角色/{角色名}.md`
- 角色关系：从情节点提取（不从原文），含演变追踪与最终状态

### Stage 5 汇总报告
`拆文报告.md`：故事线 + 节奏与情绪触动点总览 + 循环单元 + 跨章伏笔地图 + 冲突升级路径 + 可复现模块 + **写法技巧清单**（一笔两用/延迟揭示/视角欺骗/对比锚点/行为循环/身体反应替代心理描写/跨章回扣——物品意象在不同章节承担不同功能）。同时覆盖 `概要.md` 为全书 500-1000 字 plot-aware 版。

### Stage 6 文风
按 `标尺/style-profile-generator.md` 的流程生成 `文风.md`：句长/标点/对话潜台词/情绪交替周期 + 4-6 段原文锚点范例 + 分层模仿建议（硬上限 ~4000 字）。规范见 `标尺/style-profile-protocol.md`。

## 质量门（每 Stage 完成时）

- 置信度：提取内容与原文可对证（grep 原文锚点），覆盖率 85%+，重叠率 ≤35%
- 事实可溯源：关键结论必须能指回原文位置，找不到锚点的结论标注「推断」
- 摘要数 == 章节数；角色文件非空

## 下游联动（写作时）

日更写作前读：`对标/{书名}/剧情/节奏.md`（节奏锚点）+ `剧情/情绪模块.md`（情绪引擎）+ `文风.md`（文风基线）。拆文库即对标库，`对标/` 目录是项目内引用视图（详见主 SKILL.md 目录结构）。
