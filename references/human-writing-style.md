# 活人感写作（来自 human-writing skill，适配长篇小说）

> 本文件蒸馏自 `human-writing` skill（通用中文创作 / 活人感写作 1.1.0），**只取与虚构长篇相关、且不违背本工作流 `anti-ai-rules.md` 的部分**。
> 完整原文另见同目录：
> - `human-writing-fiction.md`（虚构写作专文，人物/场景/对白/设定/视角/结尾）
> - `human-writing-revision.md`（七遍改稿，初稿后读取）
> - `human-writing-formats.md`（不同文体的形式差异）
> - `human-writing-forum-prose.md`（论坛长帖体，仅用于「帖子体小说 / 第一人称故事」模式）
> - `human-writing-reality.md`（非虚构核验：真人 / 历史 / 新闻 / 数据 / 评测的事实边界，仅在非虚构或混合内容时按需读）
> - `human-writing-lite.md`（活人感规则速览，快速回顾用）
> - `scripts/check_prose.py`（prose 检查脚本，见第四节边界）

## 一、动笔前先找到叙述位置

写每一章 / 每一段前，先在内部回答下面五件事（不把答案原样交给用户）：

1. **谁在叙述这件事。** 第几人称、哪个角色的主观视角。他凭什么知道，又有哪些地方只是在推测或受限（参见「时代认知边界」与视角一致性规则）。
2. **什么让这一章现在要发生。** 可以是一条新线索、一次冲突升级、一个一直没解开的小结、或人物被迫做的选择。
3. **手里有哪些能托住这章的东西。** 优先找动作、数字、时间、地点、原话、失败、代价与后来结果。
4. **人物对哪一点有明确判断。** 这个判断依据什么，又到哪里为止。
5. **读者读完上一段，最自然会追问什么。** 后一段就去接住这个追问。

现实感来自材料与说话位置，其次才是语气。不要把「活人感」理解成口头禅、粗口、错别字和网络梗。

## 二、第一稿直接带着人写

第一稿从具体的说话者 / 视角和材料出发。像给一个感兴趣但不了解此事的人解释，边讲事情，边处理他下一步会产生的疑问。

下面是现代白话散文的默认写法（诗歌、剧本、人物对白服从具体文体，不能为了满足散文句法改坏作品；小说正文以下列为准，但破折号 / 冒号见第三节例外）：

- 开头尽快碰到事情。可以直答，可以讲刚发生的一幕，也可以从一个反常的小事实说起。不要预告全文结构。
- 除非用户明确要清单或教程，不要先把题目命名成「两个成本、三层原因、四个阶段」。分类应当来自材料，不能拿分类代替文章。
- 一段先完成眼下这一件事。它可以讲动作、补背景、算一笔账、解释原因、承认疑点或给出判断。
- 新段落必须增加一件新东西。新的事实、新的动作、新的例子、新的区别或新的后果都可以。同一观点改换说法不算推进。
- 后一段接住前一段留下的问题。推进靠材料和因果，不靠「更深一层」「真正的问题」之类路标。
- 先让主语和动作出现，再往后接时间、原因、条件和例子。长句可以有，读者要尽早知道谁做了什么。
- 让白话打底。古意从词序、停顿和分寸里自然出现，不靠生僻字、成串成语和硬塞典故。
- 动作、细节或原话已经把感情写出来，就停一下。不要追在后面替读者解释。
- 允许正常的重复、补充、自我修正和短暂岔话。每一处都要来自眼前内容，不能按固定间隔表演随意。
- 判断可以偏，可以有情绪。把依据放在附近，让读者知道这是作者的看法。
- 段落不必等长。普通地方用普通句子结束。单句成段只留给确实需要停一下的地方。
- 写到事情已经讲完就停。不要强装升华、首尾呼应或时代意义。前后照应只有在事物的作用或含义已经改变时才保留。不要在末段重新摘要全文。

## 三、成稿绝对不能出现（硬禁，含小说例外）

下面几项覆盖标题、小标题、正文、图片说明和引用转述。命中一项就不能交稿。
**先明白一件：这里禁的是修辞动作，不是字面。把一个禁用句式换一套字继续做同一个动作，仍然算命中。**

- **不写翻案腔。** 先立一个读者并没有的误解，再推翻它给下文抬价。外衣清单（举例非边界，同动作换任何字面都算）：「不是……而是……」「并非……而是……」「不在于……而在于……」「与其说……不如说……」「表面……实际……」「看似……实则……」「你以为……其实……」「回头才发现」「说到底」「答案恰恰相反」「A 不重要，重要的是 B」。判断直接从正面下，先给判断，再给依据。只有文章真的用材料走过了从误解到修正的过程，作者的自我修正才可以出现，且不能套用上面任何一种固定句式。
- **不写三项以上的同构排比。**「为什么出发，为什么放弃，爱过什么，怕过什么」这种整齐的克制服，两项为限，第三项必须换一种说法或删掉。
- **不给抽象名词配具体动词写抒情。** 时间不会保管细节，焦虑不会显出形状，岁月不会磨平什么。文章真的在写具体事物时不受影响。
- **不把动词名词化。**「完成了对流程的优化」写成「把流程改顺了」，「实现了效率的提升」写成「快了多少、省了几个人」。`anti-ai-rules.md` 的名词化检测同源，二者一致。
- **不用商业汇报和模型惯用黑话替普通事情抬价。** 赋能、抓手、闭环、底层逻辑、顶层设计、认知跃迁、降维打击、信息茧房（滥用）、情绪价值（滥用）等；`anti-ai-rules.md` 与 `human-writing-revision.md` 区分了绝对禁词与语境词，脚本不得自行增加未写明的硬禁词。
- 非虚构 / 论坛体另有「破折号、冒号、说白了、洞察路标词」等硬禁，**在长篇小说中按下述例外处理**：

### 小说例外（重要）

本工作流的 `anti-ai-rules.md` 与 human-writing 的论坛体规则在此处相反，以本工作流为准：

- **破折号 `——` 在小说中允许**，且是推荐的反 AI 手法：用于对话被打断、或「顿号清单 + 破折号收尾」打断三连排比（见 `anti-ai-rules.md` 第四节）。**不要**在小说正文里机械执行 `check_prose.py` 的破折号清零。**但必须限量**（朱雀第八版实测：AI 段每 136 字就 1 个破折号，人工段每 268 字 1 个）——每节 ≤2 个，其余停顿用句号或省略号。用量过度会反向拉高 AIGC 值。
- **冒号 `：` 在小说中允许**，用于引出人物直接台词（「他说：『……』」），这是标准对话格式。**不要**在小说正文里机械执行 `check_prose.py` 的冒号清零。
- 「说白了」「说穿了」「先说结论」仍建议删（除非是角色口吻）。
- 翻案腔、三项以上排比、名词化、抽象名词配动词抒情、黑话——**小说与论坛体一致，全部照禁**。

## 四、运行 prose 检查脚本的边界

`scripts/check_prose.py` 可直接对 Markdown / 文本稿件运行，会判定冒号、破折号、翻案句、硬停词、模型路标与黑话。

- **论坛体 / 非虚构 / 帖子体小说模式**：照脚本执行，直到禁用项清零。
- **普通长篇小说模式**：脚本的「破折号清零」「冒号清零」两项在小说中为误报，跳过；其余项（翻案句、硬停词、黑话、模型路标）仍照查。即：**脚本只负责发现形状，不能判断文章有没有人；小说模式仅把脚本的翻案 / 黑话 / 路标失败项当硬要求，散文形状警告服从本工作流文体。**

```text
python3 scripts/check_prose.py 稿件.md
```

## 五、与 anti-ai-rules.md 的关系

两份文件互补、不重复：

- `anti-ai-rules.md`：偏**检测器实战**（朱雀画像、句式指纹、代词三法、时代认知边界、叙事层面去 AI 味），针对番茄 / 网文风与具体项目沉淀。
- 本文件 + `human-writing-fiction.md`：偏**活人感底层写法**（说话位置、第一稿、人物行动托戏、成稿硬禁中的翻案腔 / 排比 / 名词化 / 黑话）。

写正文：先过本文件的「说话位置 + 第一稿」，再走 `human-writing-fiction.md` 的「人物 / 场景 / 对白 / 设定」；初稿后过 `human-writing-revision.md` 七遍改稿（跳过其破折号 / 冒号硬禁）；最后与 `anti-ai-rules.md` 的「终极自检清单」合并打勾，全部通过才能定稿。
