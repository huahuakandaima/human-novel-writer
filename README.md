# human-novel-writer

AI 长篇小说（网文/番茄风）全流程写作工作流 Skill，**v2.1（2026-10-07）**。适用于 ZCode、Claude Code 等支持 open SKILL.md 格式的 agent。

## v2.1 更新说明（2026-10-07）

v2.1 并入《小说ai行文规范》作为**文笔准绳**，并合入两条本地演进线（角色门禁、黄金三章合同）：

**新增能力**
- **行文文笔准绳（`references/xingwen/`，14 文件）**：《小说ai行文规范》全套——干打判据（动作句至少补两项）、主次判据（详略由主次决定）、称呼契约（第三人称：名字优先、叙述层禁「你」「我」）、硬性红线速查（10 字段落五例外/段长方差/比喻限额/标点配比/环境通道/设定投放/台词纪律）、36 条反 AI 味病征清单、34 条禁止清单、39 条零频套语库、收尾检查两遍、AI 扩写工作流（种子三形态 + 七条扩写原则）、亲密暧昧环节专章（8.6，优先级最高）
- **角色调研与入场门禁（强制）**：角色资料卡 10 字段 + S/A/B 研究分级 + 入场检查（角色卡未完成不写关键对白/战斗/关系转折）
- **黄金三章合同（新书强制）**：可验证的开篇承诺 → 三章交付顺序（异常落点/验证异常+旧优势失效/受限外挂+首次验证）→ 开篇读者交付检查 → 连载循环
- **自定义书籍流程（零补全模式，2026-10-07 同日增补）**：触发词「自定义开书 / 我自己设定 / 逐条问我」——AI 不得自行增加、补全、拟定任何书籍设定细节（人名/地名/组织名/金手指/关系/桥段全由用户提供），只做盘点已有、提醒缺失、逐条提问三件事；用户答不上来时 AI 点头才给候选且注明 AI 提议；作用范围仅开书建档层，正文写作仍走每章 8 步循环。标准流程（AI 起草待确认稿→用户裁决）保留不变
- **朱雀 API 在线门禁（最终门禁，2026-10-07 同日增补）**：`scripts/zhuque_check.py` 直连腾讯云 EdgeOne Makers 朱雀模型（`@makers/zhuque-text`，接口文档 cloud.tencent.com/document/product/1552/137539，每月免费 50 万 token，实测约 1.7 token/字）——本地双门禁全过后在线复测，输出人工/AI/疑似 AI 三类占比 + softmax 整体置信度 + 逐段置信度；AIGC 合计（AI+疑似）>0.5 = 判 FAIL 走删除重写制（触发仍需人工读感确认），`is_merge=false` 的高分区片段清单直接定位"已过片段不动、只重写未过片段"的病灶。Key 放环境变量 `ZHUQUE_API_KEY` 或 `scripts/zhuque_api_key.txt`（已 gitignore，严禁提交）
- **三章实战经验回流（2026-10-07 同日增补）**：①朱雀口味特征（anti-ai-rules 六之十三）——判「人工」=口语碎句/高密度数字/毒舌吐槽自由直接引语/短句参差，判「疑似AI」=工整叙述长段/闪前开场/面板叙述化/规整因果句，**初稿即按口语化语感写，往文雅工整改是负优化（实测 74.5%→80.9%→26.4%）**；②自定义流程新增 5.5 机制演练步骤（系统文/金手指收口前拿前三章场景 dry-run）；③三门禁执行顺序：本地双门禁先全绿再跑朱雀，成本策略=重点章必测普通章抽测；④density_check 新增直引号检测（中文正文主用直引号即提示转弯引号）；⑤待确认稿多轮重写加版本后缀留档

**规则调整（2026-10-07 用户裁定：与旧规则冲突处一律以行文规范为准）**
- **破折号**：废除"每节 ≤2"限量，改为**用途纪律**（插入语吐槽/对话打断/场景跳转分隔正当用途不限量，装饰性滥用才砍）
- **翻案腔**：对比类（不是…而是…等）**有信息量时合法**（空对比仍禁）；看似…实则…等语义翻转型维持硬禁
- **三连排比**：增"意象对仗收尾三连"豁免（独立短段、末项反转落点）；删"两拍排比全章 ≤2 次"限制
- **名词短句堆叠**：改为纯短语段纪律（一个场景 ≤2~3 个、不连超 3 个）
- **明喻**：废除"一禁了之"，改为比喻纪律（单段 ≤1、角色全书 ≤5 且专属化、喻体生活化）
- **普通人视角铁则**：定性修正——叙述层全知合法（称呼契约），铁则约束细节粒度（素材仍远景化）
- **门禁脚本升级**：density_check 硬项=同构三连排比/禁词/零频套语，破折号降为密度异常提示，省略号统计「……」与「......」双形态，新增 10 字段落五例外提示；check_prose 对比型翻案腔降为人工判断提示
- 扩写种子模式不受每章字数下限约束（整章循环模式维持 ≥1900 字裁定）

## v2.0 更新说明（2026-08-14）

v2.0 将 **oh-story-claudecode**（13 个网文 skill）与 **writing-dna-skill**（文风蒸馏）的可迁移能力全部并入本 skill，成为单一自包含写作引擎：

**新增能力**
- **拆文对标**：短篇/长篇拆解管道（`拆文库/{书名}/`），把爆款书拆成 剧情/节奏.md、情绪模块.md、文风.md 等对标资产；番茄题材可先用 NOVELCATCH 黄金三章拆解报告做预对标参考
- **题材库**：32 张长篇题材卡 + 10 个短篇风格包 + 题材公式（21 大公式）+ 核心梗与读者心理
- **选题（静态+NOVELCATCH 数据）**：选题四步（推荐写什么/为什么能爆/行不行/怎么验证）+ 9 维读者画像 + 平台指南；数据源 NOVELCATCH（https://novelcatch.com，番茄每日榜单/黑马/情报/赛道对比，agent 可 WebFetch 读取，样本≥15 可给"高"）；无数据时可行性最高给"中"
- **写作技法层**（`references/网文技法/`）：钩子库（章首 7 式/章尾 13 式）、爽点情绪工程（爽点六类型/高潮蓄能公式/六种情绪弧线）、读者契约（终局储备/主角代理权）、大纲结构理论（八节点/章节张弛/黄金三章）、反转工具箱、对话技法、正文技法
- **四视角审稿**：架构师/人物/叙事/一致性四视角 + 番茄/起点/知乎平台 rubric（S1/S2/S3 分级）
- **封面生成**（foxtrai 版）：题材→视觉风格映射 + 三层提示词，执行走 foxtrai 生图 API（依赖 foxtrai-生图 skill）
- **文风蒸馏**：writing-dna 六层蒸馏（语言 DNA/结构模板/认知框架/视觉风格 → Writing-DNA.md），产物落 `文风库/{作者}/`

**规则调整**
- **技法优先（试验期）**：网文技法层优先于风格/文戏类写作红线（文戏功能重复、展示而非告知、短句节制、视角受限）；内容边界类红线保留（无阴谋论、无死亡威胁、角色人设查证、新设定查重、战力自洽）
- **去 AI 味双门禁调整**：朱雀密度红线降为提示级（技法优先期），翻案腔/黑话/模型路标硬项仍必修；删除重写制触发加人工确认
- **章节合同升级**：11 问 + 3 行生产要素（情节点字数预算 / 章尾钩子类型 / 复沓锚句）
- 外挂 skill（qu-ai-wei、remove-ai-flavor）已删除——其 51 类矩阵与模板壳内容已蒸馏进 `references/anti-ai-rules.md`

## 能力覆盖

- **项目目录搭建**：一键复制 `assets/项目骨架/`（16 文件模板，含 4 个总控文件）即成新书骨架
- **自定义书籍流程（零补全）**：说「自定义开书」→ AI 只盘点缺失 + 逐条提问，全部设定细节由用户提供，经用户确认后落盘
- **三总控文件**：项目状态（单点事实源）/ 开书定位 / 核心设定
- **人物卡 9 要素**：公开目标 / 私下欲望 / 当前利益 / 害怕失去 / 底线与缺陷 / 资源与权限 / 利益冲突 / 语言指纹 / 重大刺激反应
- **大纲三件套**：全书大纲 / 分卷大纲 / 滚动细纲（只细化接下来 5-12 章；每章含 11 问 + 3 行生产要素）
- **追踪四件套**：时间线 / 角色状态 / 伏笔 / 资源与权限
- **每章 8 步循环**：LOAD → CHECK → CONTRACT → DRAFT → REVIEW → REVISE → UPDATE → DECIDE（用户裁决才算完成）
- **去 AI 味三轨**：`xingwen/00-常驻规则与总纲.md`（**文笔准绳**，冲突时以此为准）+ `anti-ai-rules.md`（朱雀画像/句式指纹/删除重写制）+ `human-writing-*.md`（活人感规则）+ `网文技法/去AI味/`（oh-story 三遍法补充）；双门禁量化（density_check 硬项=三连排比/禁词/零频套语 / check_prose 硬项=翻案空对比/黑话/路标）+ 朱雀 API 在线复测（`zhuque_check.py`，最终门禁，AI+疑似>0.5 走删除重写制）
- **扩写模式**：用户给种子（开端/总结/引导）时按 xingwen 七条扩写原则执行，忠于种子、扩写的首要动作是"长"
- **网文技法知识层**：见上"v2.0 更新说明"，入口 `references/网文技法/INDEX.md`（按需加载，不预占上下文）

## 使用方式

把本目录放入 agent 的 skills 目录（如 `~/.zcode/skills/`），然后：

- 写新书：`搭小说项目` → 自动复制项目骨架
- 自定义开书：`自定义开书` / `我自己设定` / `逐条问我` → 零补全问答建档（AI 只提醒缺失，不代填任何细节）
- 写章节：agent 按"每章 8 步循环"执行，章末跑双门禁脚本
- 朱雀复测：本地双门禁全过后跑 `python scripts/zhuque_check.py 正文/第NNN章-xxx.md`——AIGC 合计（AI+疑似）>0.5 = FAIL 走删除重写制，未过片段清单定位病灶；Key 放环境变量 `ZHUQUE_API_KEY` 或 `scripts/zhuque_api_key.txt`
- 扩写/润色一段：直接贴种子（开端/总结/引导）→ 按 xingwen 扩写工作流输出，忠于种子只补肉
- 去 AI 味：按 `references/xingwen/00-常驻规则与总纲.md`（准绳）+ `references/anti-ai-rules.md` 全量自查 + 双门禁
- 拆文对标：`拆这本书` → 拆文库/{书名}/ → 日更时自动对标（番茄题材可先看 NOVELCATCH 预对标）
- 选题数据：`帮我选题` → 自动读 NOVELCATCH 榜单（或你粘贴数据）→ 选题四步跑数据模式
- 选题：`帮我选题` → 选题四步（静态，无榜单时给"中"）
- 审稿：`审一下` → 四视角审稿
- 封面：`做个封面` → foxtrai 生成
- 蒸馏文风：`蒸馏XX作者的文风` → 文风库/{作者}/
- 去 AI 味：按 `references/anti-ai-rules.md` 全量自查 + 双门禁
