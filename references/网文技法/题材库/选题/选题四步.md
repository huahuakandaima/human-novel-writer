# 选题决策（静态版，改编自 oh-story story-long-scan/topic-decision）

> 来源：oh-story-claudecode `story-long-scan/references/topic-decision.md`（已去工程化：无扫榜采集、无 Phase 5、无 story-* 联动，输入改为静态双源）
> 用途：用户说"帮我选题""写什么能爆"时，产出 `选题决策.md`——**推荐写什么、为什么能爆、行不行、怎么验证**。

## 决策路由

| 你在做什么 | 看这节 |
|-----------|--------|
| 从题材库/用户数据里挑方向 | 选题四步 |
| 判断一个方向行不行 | 可行性判断 |
| 没数据、纯靠知识库 | 内置知识模式（默认） |

## 输入双源

1. **静态参考**：`题材库/题材索引.md`（题材总览）+ `题材公式.md`（21 大公式）+ `核心梗与读者.md`（读者心理）+ `题材趋势.md`（流派参考，标注"候选假设"）
2. **用户提供的数据**（可选）：榜单截图、链接、自述"最近 XX 火了"——有数据时按数据说话，无数据时走内置知识模式

## 选题四步

每个推荐选题都走完这四步，缺一不可：

1. **能爆的原因（先当假设）**：从**重复出现的样本**（排除单本个例）+ 新元素提取，推出"这个方向能爆，依靠 X 结构/梗/人设吃这波读者"。单本爆款只是个例，多本重复才算信号。这里只写假设，标 `待验证`。
2. **市场验证**：用户提供的数据里同方向有几本 + 趋势（↑/→/↓）+ 反例（同方向有没有扑街/烂尾的）；无数据时按题材库认知给"候选假设"。
3. **差异化定位**：作者优势 × 市场缺口 = "你的版本和现有的不同在哪"。没有差异化 = 同质化挤不进去。
4. **可行性 + 风险 + 验证动作**：给出可行性高/中/低（下节规则）、最可能的失败点、开写前怎么低成本验证（通常："先写黄金三章测追读，不行就换"）。

## 可行性判断

分三档；**样本不够时不许给"高"**，别让几条数据撑出假信心：

| 可行性 | 含义 | 条件 |
|--------|------|------|
| 高 | 可放心写 | 用户数据样本够（≥15）+ 趋势↑或→ + 作者素材能撑 + 有差异化空间 |
| 中 | 可写但先验证 | 样本够但趋势↓ / 差异化不清 / 作者素材半撑 / **仅靠静态知识库** |
| 低 | 不建议 | 同方向已饱和（扑街反例多）/ 作者素材撑不住 / 平台调性不符 |

**硬规则**：无实时榜单、纯凭知识库趋势时（内置知识模式），**所有方向一律给"中"**，理由写"基于通用认知，无榜单验证，开写前必须先小成本试水（黄金三章）或提供榜单数据"。不许给"高"。

## 选题决策.md 模板

```
# 选题决策：{方向}
- 数据来源：{用户提供数据 / 内置知识（候选假设）}
- 日期：{YYYYMMDD}

## 推荐选题

### 选题 1：{一句话方向}
- 题材组合：{主类型 + 副类型/梗}
- 目标读者：{9 维画像，见 读者画像.md}
- 核心卖点：{读者为什么追}
- 能爆的原因：{X 结构/梗为什么吃这波}（假设，`待验证`）
- 差异化定位：{和现有的不同在哪}
- 可行性：高/中/低 — {理由，写清依据}
- 失败风险：{最可能崩在哪}
- 验证动作：{开写前怎么低成本验证}
- 篇幅/平台：{建议字数区间 + 目标平台}

### 选题 2 ...
### 选题 3 ...
```

2-3 个选题为宜，按可行性排序（高的在前）。

## 交付

1. 产出 `选题决策.md` 到小说项目根目录（无项目则用户指定目录）
2. 告知用户：下一步是「开书定位」（01-开书定位.md）+ 拆文对标验证"能爆的原因"（拆文对标/长篇拆文.md）
